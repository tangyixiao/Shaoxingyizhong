# 绍兴一中网站手机版操作设计

> 版本：2026-10-16 · 原站忠实适配版  
> 状态：设计草案，供评审和后续实现使用。  
> 本次交付仅为本文档；未修改页面、样式、脚本、构建或发布流程，也未进行手机端实现验收。

## 1. 设计立场

**让原来的绍兴一中网站能够在手机上正常操作。看起来、组织起来、读起来，仍然是原站。**

“原教旨主义”落实为：保留原站的校名校徽、棕褐与米金配色、校园背景、导航层级、栏目名称、栏目顺序、列表形态、正文内容和链接目的地。只处理窄屏放不下、触屏点不到、内容被裁切和鼠标悬停无法操作的问题。

允许改变的是容器宽度、排列方式、必要的触控面积，以及把悬停操作补充为点击操作。每项变化都应能指向一个具体的手机使用障碍。

### 1.1 方案取舍

| 路线 | 结果与代价 | 本文选择 |
| --- | --- | --- |
| 整张桌面页面等比缩小 | 保留大屏构图，但字和链接过小，手机仍需放大和平移 | 不作为手机默认方案 |
| 保留原站外观与组织，做最小响应式适配 | 分栏在窄屏顺序展开，原导航和原列表仍可辨认，触屏能完成操作 | **采用** |
| 重新设计为手机门户或 App | 需要重新组织首页、导航与操作习惯，偏离原站 | 不纳入本方案 |

### 1.2 明确边界

- 覆盖：首页、全站导航、栏目与分页、搜索、文章阅读、图片表格、附件、原有校内服务入口、页脚。
- 不新增账户体系、收藏、阅读历史、推荐流、标签筛选、消息中心或底部 Tab 栏。
- 不新增首页“热门”“精选”“最近浏览”等分组；不把原列表改成通用圆角卡片流。
- 不重写文章、摘要、标题、署名或日期；不恢复原页面中已经注释掉的模块。
- 不改变现有文章编号、栏目路径、附件路由、爬虫同步和历史归档规则。
- 本文的设计数值是后续适配的建议约束，不代表已经实现，也不宣称通过了实机测试。

## 4. 全站布局与触控约定

### 4.1 屏幕范围

| 可用宽度 | 布局规则 |
| --- | --- |
| 320–767 CSS px | 手机主范围。单列正文，导航换行，页面左右留白建议 12–16px |
| 768–1199 CSS px | 过渡范围。保留能够容纳的原分栏；一旦内容、点击区或长标题互相挤压，就按原顺序降为单列 |
| 1200 CSS px 及以上 | 保持现有桌面呈现，本方案不顺带清理桌面样式 |

断点用于约束适配，不根据设备型号切换不同网站。横屏仍访问相同地址；输入方式为触控时，子菜单不能重新变成只能悬停。

### 4.2 操作尺寸与内容边界

- 主要可点击区域建议至少 44 × 44 CSS px；图标本身可以维持原站大小，通过留白扩大命中区域。相邻区域不重叠。
- 搜索输入和正文基准字号建议为 16px；列表主标题为 15–16px；日期等次要文字为 12–14px。文章标题建议 22–24px，可完整换行。
- 普通正文行高建议 1.7–2.0。保留原文的标题、加粗、颜色和层级；仅在内联固定字号或行高确实使手机无法阅读时作局部修正。
- 不禁止浏览器缩放，不把 `zoom:0.8` 或整页变换作为手机版方案。手机规则要覆盖原有缩小行为，桌面范围保持原样。
- 页面整体不出现横向滚动。宽表格、原图等确有必要横移的内容，限制在独立区域或原图页面内。
- 不用全局隐藏横向溢出的方式掩盖内容丢失，不以隐藏文字、删列或省略正文换取“没有滚动条”。
- 默认所有内容随页面滚动，不新增吸顶大栏、悬浮按钮或底部固定操作条。

## 5. 首页与全站导航

### 5.1 页头

从上到下继续保持“顶部日期及链接 → 校徽校名与原有登录区域 → 搜索 → 主导航”的关系。桌面上原本左右并列的元素，手机上换行。

顶部日期保留。常用链接首先按原顺序换行显示；链接组过长时，可提供一个明确的“常用链接／收起”文字按钮，由用户主动收起或展开。首次进入默认展示全部原链接，名称与顺序不变。这个按钮只用于适应窄屏，不新增服务分类。

校徽校名完整置于页头；搜索放在其下方，占可用宽度。登录、注册、会员等区域只按原站实际状态展示，不能为了补齐界面虚构登录成功、未读数或用户资料。

### 5.2 主导航

**默认常显全部十项导航，使用原棕褐导航条多行排列。** 不把整组导航默认藏进汉堡菜单，也不改成横向滑动后才看得到后半部分。

每项以能容纳原标签、必要展开按钮及触控留白为准，建议最小宽度约 120px：320px 屏幕通常为两列，390px 屏幕通常为三列，具体以真实内容不挤压为准。最后一行空余位置保留背景，不增加虚构入口或放大某个栏目制造突出。

父栏目分成两个不重叠的操作区：

| 操作 | 结果 |
| --- | --- |
| 点击栏目文字 | 按原链接直接进入该栏目，不先吞掉点击要求再点一次 |
| 点击旁边的小展开符号 | 在导航条下方显示该栏目的原有子菜单，不跳转 |
| 再点展开符号 | 收起该组子菜单 |
| 展开另一组 | 收起上一组，显示新组 |
| 点击子栏目文字 | 按该子栏目的原链接进入 |

展开区域沿用原米棕底和棕褐字色，随页面排版，不覆盖正文。子栏目多时自然换行，不删项。展开符号要有可读名称和展开状态，支持键盘操作；不依赖拖动或长按。

当前页面的选中态沿用原样式；没有子菜单的“首页”等入口不出现展开符号。

### 5.3 首页内容

- 原栏目框架、题头和“更多”入口保留。多栏变单栏时，每个栏目独立成段，仍使用原来的列表与分隔形式。
- 原首页存在的栏目切换，保留其原位置、标签与默认选中项。悬停切换补充为明确点击切换；切换标签与“更多”链接各自执行原含义。
- 标题最多自然占用所需行数，优先完整显示；如果源内容本来已经被截断，界面不得自行补写未知的剩余文字。
- 日期不与长标题重叠：容纳不了时移到该条目的下一行，保留原日期内容与格式。
- 图片等比显示，不裁掉图片中的文字。纯装饰背景可裁切，图文信息图不裁切。
- 原轮播若有自动切换，尊重系统减少动态效果设置；保留可点的原上一张、下一张和序号入口。点序号不应误打开文章，图片链接仍执行原链接。滑动不作为唯一操作。

## 6. 栏目、列表与分页

### 6.1 从侧栏到手机栏目区

保持“栏目导航 → 推荐阅读 → 主列表”的原有区域关系，手机上依次纵向排列，不把推荐阅读变成新的推荐流。

栏目导航的原题头和当前栏目保持可见。栏目较多时，题头增加独立的“收起栏目／展开栏目”操作；首次进入默认展开，用户主动收起时只收起完整导航列表，当前栏目仍可见。展开后显示全部同级项目，保持原顺序和选中态。直接点击原题头链接仍进入原父栏目。

推荐阅读保留原名称和条目顺序，首次进入默认展示。若推荐区较长，可提供同位置的“展开／收起”，由用户主动减少占高；不以手机版为由自动藏起原内容。收叠只改变显示状态，不删除原内容。

面包屑保留完整父子关系，允许多行显示。没有必要压成一个没有层级的返回箭头。

### 6.2 列表操作

1. 进入原栏目地址，显示原栏目标题、原排序的条目和原日期。
2. 点条目标题进入文章，链接继续采用源页面的打开方式。
3. 返回时，优先由浏览器恢复原分页与滚动位置；需要补充恢复机制时，只保存当前会话状态，不新增“阅读历史”功能。
4. 当前栏目长标题可换行，不用跑马灯。列表留白承担触控面积，不增加大面积按钮底色。

单条目内标题与日期仍是一条信息，不拆成互不相干的卡片。只有标题链接和确有原始链接的图片可跳转；不在包含多个不同链接的整块区域叠加一个大链接。

原条目中的栏目名称链接、加粗标题、推荐／热门／最新小标记及置顶顺序继续保留，不把原有标记重新解释成本站计算的实时热度。

### 6.3 原栏目搜索

有栏目搜索的模板，仍在原主内容区、面包屑之前显示。保留原“栏目搜索”名称、栏目下拉框、检索字段下拉框、关键词输入与搜索按钮，空间不足时逐行排布，不默认收进新面板。

栏目选项保持该下拉框本身的原顺序与范围，不拿侧栏顺序覆盖；字段保留“文章标题、文章内容、文章作者、录入者、关键字”的原选项与默认值。继续使用系统原生下拉操作，不重绘为标签筛选。

该搜索原提交路径为带有 `searchtype`、`ModelId`、`nodeId`、`Keyword`、`fieldOption` 参数的 `/search.aspx`，与页头的 `/search/s.aspx` 不同。后续实现必须分别遵守原契约，不能把两者合并为仅标题搜索。输入保留、空值反馈和可用性降级遵循第 7 节；静态部署中给 `search.html` 添加参数本身不会产生检索结果。

### 6.4 分页

保留原“首页、上一页、页码、下一页、尾页”等控件及语义，增大点击范围，空间不足就换行，不替换为无限滚动或自动加载。

- 栏目已有 `Index_2.aspx` 一类独立分页地址，部署后沿用相应的 HTML 路径。
- 搜索页的查询参数分页与栏目文件分页不是同一机制，不能统一改成不存在的 URL。
- 只对有真实目标页的链接提供跳转。边界页不得出现可点击但无效的上一页或下一页。
- 页数与总数只能来自页面或有效数据，不能推算成未经验证的实时统计。

## 7. 搜索

### 7.1 页头搜索与共用操作规则

页头搜索框保留在原页头区域，仍为关键词输入和搜索按钮，保持它原来按标题检索的含义；第 6.3 节的栏目搜索保留自身的范围和字段选择。不增加搜索抽屉、热门词、联想推荐、最近搜索、标签筛选或新的结果排序。

手机操作规则：

1. 点输入框时保留已有输入，不延续原 `onfocus` 每次清空的行为。原提示文字改作输入提示，不作为真正提交的关键词。
2. 点击搜索按钮或软键盘搜索键执行同一个提交动作；纯空白输入不提交，在输入框附近显示“请输入关键词”。
3. 中文、空格和常见标点不得因地址处理而丢失；查询状态要能随结果页地址返回。是否编码转换由后续实现依据真实后端契约处理，不在设计中另造接口。
4. 结果继续使用原有标题、日期列表和分页；只有数据确实返回零项时才显示“未找到相关内容”。
5. 进入结果文章后，按原打开方式返回；同页导航应恢复关键词、结果分页和浏览位置，新页面则关闭该页面回到原结果页。

### 7.2 静态归档能力边界

当前文件显示两类搜索都需要原站后端：页头所需的 `search/` 路由未包含在本地归档中；栏目搜索指向的 `search.aspx` 虽有静态快照，也不能执行服务端查询。单独改写 `.aspx` 为 `.html` 不会生成检索能力，已有 `search.html` 内容也不能证明任意关键词可搜索。

| 部署条件 | 设计行为 |
| --- | --- |
| 已有并验证可用的原站搜索后端 | 沿用原检索契约，执行上述输入、结果和分页流程 |
| 静态归档未接入可用检索能力 | 保留搜索框的原位置和样式，在附近明确显示“归档版暂不支持关键词检索，请通过栏目浏览”；搜索提交不可执行，不能跳往已知缺失的地址 |
| 后端出现可识别的请求失败 | 保留输入，显示“搜索暂时无法使用，请稍后重试”，不伪装成没有结果 |

结果页若只是抓取快照，应标明“归档结果快照”，不把其中的空关键词或旧总数表现为用户刚刚搜索得到的结果。

搜索能力是否启用必须依据实际部署配置和验证，不通过一次失败请求就判断永久不可用。新增本地检索索引或外部搜索服务属于另一个功能需求，不包含在本方案中。

## 8. 文章阅读

### 8.1 保留原阅读层级

顺序仍为：面包屑与栏目标题 → 文章标题／已有副标题 → 原来源、作者、发布时间、点击数等信息 → 正文 → 原打印及已有操作 → 上一篇／下一篇 → 原相关信息与页脚。

- 保留居中的棕褐文章标题，完整换行，不增加封面、阅读时长、标签或“编辑精选”。
- 元信息自然换行，保留已有值。空值不补造作者、来源或点击数；动态点击数不可取得时不显示虚构的 `0` 或持续加载状态。
- 正文取消左右多层固定留白，使用实际可读宽度；保留原段落、缩进、编号、强调和链接样式。
- 长网址、文件名可在合适位置断行；不得为了排版改写链接目的地。
- 原“【打印正文】”保留为文字操作，不变成突出主按钮。能否打印遵循浏览器实际能力，不承诺一定导出 PDF。
- 上一篇／下一篇上下排列，长标题换行；原“没有了”等边界含义保留。

### 8.2 图片与图像形式通知

正文图片等比适应可用宽度，不能拉伸、裁字或转成装饰背景。对于课表、考试安排等整图文字内容，允许通过轻量的“查看原图”文字链接打开同一资源，继续使用浏览器自身缩放。

原图地址必须使用构建后有效的图片地址；不能把缩略图地址猜改成另一个文件名。若源内容本来已有图片链接，以原链接为准，不覆盖其目的地。

不新增沉浸式图库、手势翻页或全站灯箱。图片失败时，在能够检测失败的原图片位置显示简短提示和有效的重试／原图入口，不移除整段正文。

### 8.3 宽表格与嵌入内容

| 内容 | 手机处理 | 保真要求 |
| --- | --- | --- |
| 普通文本表格 | 能自然换行的单元格先换行 | 保留行列顺序、表头、边框、单元格内容 |
| 复杂考试安排等宽表格 | 表格独立横向滚动，首处附“表格可左右滑动查看”的轻量提示 | 保留合并单元格、行列对应和原有配色；不拆成卡片，不删列，不整体缩成小字 |
| 图片表格 | 按图片等比显示，提供上述原图操作 | 不做 OCR 替换，不自行重建数据 |
| 原视频或其他嵌入 | 宽度适应正文，保持比例及原内容入口 | 原浏览器不支持时说明实际限制，不伪装已播放成功 |

横向拖动仅在表格区域内移动表格，纵向划动仍能滚动文章；不能因表格处理锁住整页。实现验收必须覆盖同时存在横向表格和纵向正文的真实页面。

## 9. 附件与原有校内入口

### 9.1 附件保持正文内链接形态

原来的“学生准考证”等附件仍在原段落位置，以原文链接呈现，不集中搬到新增“下载中心”，不改成文件卡片。

- 长文件名允许换行；如有可确定的扩展名，可轻量补充“XLS”“PDF”等类型说明。没有可靠数据时不补充文件大小、预览页数、更新时间或下载次数。
- 点附件优先执行原链接，由浏览器按格式决定打开、交给其他应用或下载；不为每个文件强制增加中间确认页。
- PDF 是否可内嵌预览、Office 文件能否直接打开，取决于设备与浏览器。界面不承诺统一预览，也不引入第三方转换服务。
- 新增反馈只能描述已知事实；普通网页不能可靠获知系统下载是否完成，因此不弹“下载成功”。
- 浏览器显示资源错误时，仍可返回原文章；只有应用确实能确认的失败才显示站内错误文案。跨域原生链接的失败不承诺可在站内自动捕获。
- 继续使用既有 `downloads/` 与图片分片路由；不修改原件内容或用新附件覆盖历史文件。

### 9.2 校内系统与公共文件夹

保留顶部及页尾的原入口及其顺序，同名或重复入口不擅自合并。对已知校内地址可附小字说明“校内网络”，对“公共文件夹”说明其为原 FTP 入口。

“公共文件夹”当前目标为 `ftp://10.176.17.3/`。手机浏览器不一定支持 FTP，也不一定能访问校内网络。保留原名称、目标与点击后由入口页重定向的原行为，只在入口附近补充“校内 FTP，需网络与浏览器支持”的小字说明。不新增中间确认页、目录页或应用安装引导。

该说明不代表本站托管了文件夹内容。访问不受支持时，由浏览器提供实际反馈；不能承诺站内能检测协议是否成功打开。手机适配也不新增文件浏览、上传或认证流程，不把未知状态统一写成“服务已下线”。

外部网站、非标准端口和其他原有服务，只标明可以确认的条件。不能仅凭链接写法就断定当前可用或不可用。

## 10. 返回、状态与降级

### 10.1 链接打开方式

忠实保留源页面的 `target` 语义，不把所有内部链接统一改成同页或新页。

| 原行为 | 手机预期 |
| --- | --- |
| 原同页跳转 | 浏览器返回回到原页；保留实际地址、分页，尽量恢复滚动位置 |
| 原新页打开 | 原列表留在原页；必要时用文字辅助说明新页打开，用户关闭新页回到列表 |
| 原附件或外部协议 | 按浏览器处理；返回原页面后仍能继续阅读 |
| 直接从外部链接进入文章 | 面包屑仍可回到真实所属栏目；不依赖不存在的上一页，也不编造“返回搜索结果” |

不劫持浏览器返回键，不增加必须退出的全屏覆盖层。菜单的收起动作不应制造需要多次返回才能离开页面的历史记录。

### 10.2 状态文案与静态降级

| 状态 | 处理原则 |
| --- | --- |
| 原栏目为空 | 保留栏目题头与导航，显示“暂无内容”；不能与网络失败混为一谈 |
| 加载确实需要等待 | 只在对应局部显示简单文字提示，不给静态文章套加载骨架 |
| 图片失败 | 原位提示，不遮住其他内容，不无限重试 |
| 附件失败 | 在能确认失败的地方说明；否则尊重浏览器错误与返回行为 |
| 搜索无结果／不可用 | 依第 7 节分别处理，不共用“暂无内容” |
| 登录、点击数等动态能力不可用 | 不阻塞已归档文章与导航；不展示假的实时状态 |
| 脚本未运行 | 首页与原始链接、文章、附件继续可读可点；子菜单和收叠区必须有可访问的静态退路 |

搜索降级和校内入口说明只占必要空间，不把整个页面变成大幅提示页。所有新增辅助文案使用与原站一致的克制文字样式。
